# Agent Notes

设计与决策记录，不是项目文档。

`docs/` 只陈述**当前状态**：规范、口径、契约、验收清单。而「为什么这么定、当时否掉了什么、
后来怎么变的」，代码和 docs 都放不下——放这里。

## 放什么

- 动工前的设计稿：要做什么、备选方案、为什么选这个、代价是什么。
- 技术选型与架构决策的**过程**：`docs/dev/tech-decisions.md` 只留结论，过程写这里。
- 明确否掉的方案：留着防止以后重新踩一遍。

## 不放什么

- 当前事实（架构、组件、命令、口径）→ `docs/` 与 `AGENTS.md`。
- 用户可见的变更 → `CHANGELOG.md`。
- 待办清单、进度、人名 → issue。

## 生命周期

```text
.agents/notes/
├── proposed/     提案，还没实现；或只实现了一部分
├── implemented/  已落地；只补事实（路径、类名、默认值），不改当初的决策
└── rejected/     考虑过并否掉；只在它能防住某个诱人的错误时保留
```

## 命名与写法

- 文件名：`YYYY-MM-DD-主题.md`，日期取**首次提出**的那天。
- 顶部写一行结论，然后按 `背景 → 备选方案 → 决定 → 代价/风险 → 验证方式` 写。
- 用相对链接互相引用，不写"见第 3 节"这类会失效的指代。

## 和 docs 的边界

一份设计落地后：

1. 结论合并进 `docs/`（口径进 `docs/dev/`，技术取舍进 `docs/dev/tech-decisions.md`）；
2. 笔记移到 `implemented/`，只补事实同步；
3. `docs/` 里不保留"曾经打算这么做"的叙述。
