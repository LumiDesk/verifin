# 统一设计第二轮：信息密度研究

2026-09-05。状态：研究与下一轮试验建议，尚未修改页面实现，也不是已批准的正式规范。

- [Copilot Money 官方产品展示](https://www.copilot.money/)及[首页说明](https://help.copilot.money/en/articles/6045480-dashboard-tab-overview)：查看了官方展示中的交易、摘要等界面示例。可借鉴圆角容器内部的紧凑行、金额对齐，以及首页围绕待处理交易与支出状态组织内容。
- [Things / Cultured Code 官方产品界面](https://culturedcode.com/things/)：查看了手机和桌面的列表截图。可借鉴使用分组标题、统一对齐、少量语义色建立秩序，而不为每一项增加独立容器。

## 对第一轮方案的修正

统一设计不应同时把所有层级放大。当前候选方案叠加了：页面边距 14→20、卡片内边距
13→18、Header 52→64、首页主金额 26→40、首页摘要前间距 10→24，以及更高的交易行。
仅普通卡片两侧的外边距/内边距变化，就额外占用 22dp 横向空间。

圆角从 8→20 本身不决定容器高度；它增强了“大块卡片”的感觉，而过大的内边距、
重复标题、给简单状态使用完整图表，才是纵向空间消耗的主要原因。

建议方向：有明确主次的紧凑布局。玻璃控制层保留，内容表面圆角适中，列表和摘要紧凑，
主金额仍醒目。不要用整体缩小字体补救密度，也不把不同任务强行改成同一种页面结构。

## 下一轮候选参数（待验证）

| 项目 | 当前候选 | 第二轮试验目标 |
|---|---|---|
| 内容卡片圆角 | 20dp | 14–16dp；菜单/底部弹层可保留 20–24dp |
| 页面水平边距 | 20dp | 16dp，继续让标题与内容对齐 |
| 卡片内部边距 | 18–20dp | 12–14dp，主摘要必要时用 16dp |
| Header 高度 | 64dp | 52–56dp，随实际文字/大字号留出必要高度 |
| 页标题 | 22dp | 20–22dp，不做全局小字号压缩 |
| 首页主金额 | 40dp | 32–34dp；记账输入金额可继续较大 |
| 分组间隔 | 多处独立间距 | 同组更紧、不同组更松，优先用 8/12/16 的节奏 |
| 双行交易 | 当前增加了纵向 padding | 试验约 56–64dp，实际触控区域不低于 Android 的 48dp 目标 |

数值必须服从文本内容、长金额、英文和大字号，不用固定高度裁切内容。

## 页面调整重点

1. 首页：月份/概览等上下文减少重复；总览尝试控制在约 240–280dp。预算先用紧凑的
   执行摘要表达金额和状态，详细圆环/趋势留在预算页。最近交易采用同一分组内的连续行。
   日历保留，但建议作为后续信息；尊重已有面板开关和用户排序，不自动重排用户配置。
2. 资产：缩紧净资产标题、主金额与资产/负债摘要的间隔；保持账户余额对齐，账户行不
   再各自扩成大卡片。资产趋势与摘要使用同一信息组，图表高度按用途决定。
3. 看板：分类图与分类排行属于同一组，可减少重复标题、边距和容器；不通过把多个图
   压成不可交互的小图来节省空间。空态应短小明确，无预算不占一个完整空圆环。
4. 我的：保留四列宫格与原入口顺序，只调整图标尺寸、图文间距、卡片内边距；保留
   文字完整性和触控区域。不会再次改为列表。
5. 记账：保留分类胶囊、主金额和底部保存。只收紧分区间距；单手操作空间、表单状态
   和键盘不会为了密度被压缩。与详情页统一视觉令牌，保留各自任务结构。

## 验证方式

- 先只做首页的第二轮对照，确认密度后推广到其他页，避免再次同时修改所有尺寸。
- 同一套数据、同一 393×852 视口对比；再检验 360dp、浅/深色、英文及大字号。
- 用多天交易、多账户、正常/超支预算、长备注、长金额和空态分别验证。一条测试交易
  的大图表容易放大“空”的观感，不能作为唯一依据。
- 默认字号和标准测试数据下，首屏目标是清楚展示本月概况、预算摘要和至少 2–3 笔
  最近交易；这是试验验收目标，需实际渲染验证，不承诺所有数据/字号都满足。
- 不增加 Web 专属说明，不改变宫格结构，不改动账目计算或持久化逻辑。
