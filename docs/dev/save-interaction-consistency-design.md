# 编辑与保存交互一致性

Veri Fin 的编辑行为统一为「先改页面草稿，明确保存后才写 Controller/SQLite/KV」。有未保存修改时，Header 返回、Android 系统返回与预测性返回走同一套拦截逻辑。

## 三类操作

### 编辑会话

用户进入页面或弹窗修改一组数据，最终可以保存或放弃。每个编辑会话必须有：

- 初始快照；
- 当前草稿；
- 基于「当前草稿是否等于初始快照」的脏状态（用户把字段改回初始值即恢复为未修改）；
- 唯一明确的最终提交动作；
- 退出时的未保存修改处理。

### 明确业务命令

以下操作是用户明确要求立即执行的命令，可在自身确认后立即提交，不要求回到父页面二次保存；破坏性命令仍须确认框：

- 删除、清空、初始化、导入、恢复；
- 立即备份、立即上传、下载、检查更新；
- 标记退款已到账、信用账户还款、调整账户余额；
- 启用/停用应用锁等必须即时影响安全状态的流程；
- 新增/重命名弹窗中点击该弹窗自己的「确认/保存」。

### 临时界面状态

以下状态不参与保存与退出拦截：搜索词、筛选条件、报表周期、图表选中点、当前 Tab、临时展开/折叠、选择器内导航层级、输入法焦点、滚动位置、加载/错误提示、多选模式中尚未执行的选择集合。若某个「展开/折叠」会持久化为偏好，则属于可保存偏好，须在实现前明确。

## 统一规则

### 全屏编辑页

- 普通全屏编辑页在 `VeriHeader` 右侧使用 `SaveHeaderAction`：软碟语义的 `Icons.save_outlined` 与「保存」tooltip，不用对勾表达保存。快速记账 `EntryDetailPage` 是单手高频流程的例外，使用底部固定主按钮，保存语义、Guard 和原子提交不变。
- 所有字段只改页面内草稿；保存前不得调用持久化 Controller API。
- 保存成功后默认退出当前编辑页。
- 草稿未变化时返回直接退出；有变化时 Header 返回、Android 返回与预测性返回统一弹出未保存修改对话框。
- 新建页是否视为脏由「用户是否实际改变初始草稿」决定；新建记账和信用账户还款在进入页面时已携带待创建的业务数据，因此把「尚未创建的实体」本身视为脏。

### 弹窗和底部 Sheet

- 弹窗内编辑先落在弹窗自己的局部状态；必须有明确的「保存/确认」按钮，点击遮罩、下滑关闭或系统返回都不保存。
- 有修改时尝试关闭，采用与全屏页相同的退出询问。
- 若 Sheet 是父编辑页的一部分，Sheet 的「保存」只更新父页面草稿，不能绕过父页面直接写 Controller。
- 若弹窗本身就是完整、独立的编辑会话（例如重命名标签），弹窗「保存」可作为最终提交动作。

### 未保存修改对话框

三个动作：

| 动作 | 行为 |
|---|---|
| 保存 | 校验并提交；成功后退出；失败时留在原页 |
| 不保存 | 丢弃本次草稿并退出 |
| 取消 | 关闭对话框，继续编辑 |

点击对话框外部或系统返回等价于「取消」。保存按钮因校验失败不可执行时，应关闭对话框并把用户带回具体错误字段。异步保存期间禁止重复提交和重复弹窗。

### 保存成功与失败

- 「保存成功」以对应 SQLite/KV 写入完成为准，而不只是 Controller 内存已变。
- 保存失败时：记录隐私友好的 `AppLogger`、显示用户可见错误、保留草稿和 dirty 状态、停留在当前页面。
- 不允许页面先退出，随后只在上一级页面提示「保存失败」。
- 批量修改多个表/多份偏好应使用单个 Controller 聚合 API；涉及账目多表时必须通过 repository 事务保证原子性。

## 共享件

- `SaveHeaderAction`：全屏编辑页统一保存动作；
- `UnsavedChangesGuard`、`EditorExitController`、`showUnsavedChangesDialog`：统一 Header 返回、系统返回和预测性返回；
- `SortModeHeaderActions`：分类、标签和账户分组管理页的排序入口、取消与显式保存。

## 接入范围

全屏编辑、设置和排序页面均改为局部草稿后明确保存，包括：记账与交易详情、账户新增/详情、个人资料、主设置、AI 设置、提醒、预算设置、首页概览自定义、面板设置、数据管理偏好、周期规则及启停、还款、导入预览、分类/标签/账户分组排序、资产显示设置。所有全屏保存入口使用 `Icons.save_outlined`。

资产页是浏览页：分区展开/折叠只是本次浏览状态；视图模式、背景、分区顺序和账户顺序集中到 `AssetDisplaySettingsPage` 一次保存。创建、重命名、删除、导入、备份、还款、余额调整、待退款核销和应用锁等仍是独立明确命令。

交易详情把交易字段、关联退款和附件组成同一个页面草稿；退款 Sheet 与附件编辑只回写父草稿。`VeriFinController.saveEntryAggregateDraftResult` 在提交前校验退款/附件归属，并仅从已到账退款重新派生 `refundedBaseAmount`；`LedgerRepository.saveEntryAggregate` 在同一个 SQLite 事务中替换交易与附件，事务成功后 Controller 才统一更新内存并通知。

## 验收

- 编辑页修改后点击 Header 返回、Android 系统返回或预测性返回，都出现「保存 / 不保存 / 取消」；保存成功退出，不保存丢弃草稿，取消继续编辑；保存失败留页且草稿不丢。未修改或改回原值时直接退出。
- 删除、初始化、导入、立即备份、还款、余额调整、待退款核销和应用锁等明确命令在自身确认后立即执行；即使父页另有未保存草稿，命令完成后也不再弹未保存提示或把已删除实体保存回来。
- Android Header 返回、系统返回和预测性返回的动画/手势体验列入 release APK 真机验收。
