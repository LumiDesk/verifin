# 统一设计候选方案

状态：待用户评审，默认关闭。分支 `talyra42/unified-design-preview`。
用户反馈第一轮密度偏低后的研究见 [信息密度研究](design-density-research.md)；第二轮已先应用到首页，其他页面保持第一轮方案。
该方案直接使用正式页面、Controller 和仓储，不重建 UI Lab，也不引入演示数据层。

## 当前问题与方向

### 第二轮：首页紧凑化

仅在预览开关启用时：首页页边距 16dp、Header 56dp、卡片圆角 16dp、内边距左右 14dp、
上下 10dp。总览标题与日期并排，主金额 32dp，三项小指标保留带底色的方块，交互趋势图
96dp。预算保留紧凑圆环，中心显示使用比例，旁边显示额度/状态摘要；未设置预算时
保留空环与短说明，分类风险提示仍保留。最近交易展示 3 笔，通过
原入口进入完整列表；用户的面板顺序和开关不被重写。“我的”宫格不变。
首页概览配置页中的内嵌预览同步复用 `HomeTrendPanel`，以保持配置预览与首页一致。

演示数据：[preview-transactions.csv](preview-transactions.csv)，固定为 2026 年 8–9 月，
18 笔，包含收支、转账、跨月和长备注；账户以“演示”命名，全部附“演示”标签。
通过数据管理 → 导入账单文件 → CSV 模板 → 确认导入追加，不使用恢复覆盖。
不要重复导入同一文件以免重复计数。2026-09-05 本轮已在浏览器追加一次，原有 1 笔
测试交易保留，当前共 19 笔；另将本月预算设置为 5000，仅影响该浏览器预览数据。

第二轮验证：默认测试 915 项通过（紧凑布局专用测试在默认构建中跳过）；开启预览
后，演示 CSV 解析、首页首屏布局及四组真实记账流程通过。393×852 的标准数据下，
总览高度不超过 280dp，3 笔交易与预算摘要均位于浮动导航上方，点击预算仍进入详情。
组件接口仅参数化扩展，未新建页面副本或新增持久化逻辑。

首页保留用户指定的主金额、彩色小指标块和预算圆环；通过减少纵向留白、弱化边框和
取消曲线光晕来控制密度，不再通过删掉这些视觉结构来“简化”。
快速记账已采用轻量分类胶囊和渐进展开信息，但其余页面仍多用紧密卡片与较小字号。
“我的”的工具宫格、设置行、交易详情之间，也缺少稳定的信息密度。

候选方向是清晰的实体内容搭配浮动控制层：保留现有玻璃导航的材质和指针状态机，
减少内容区的装饰，统一卡片、标题和输入控件。不同任务仍允许不同骨架：快速记账
强调连续输入和底部保存；已保存交易详情强调逐项检查，不强行做成相同布局。

| 层级 | 候选规则 | 落点 |
|---|---|---|
| 画布 | 浅色中性灰、深色中性黑，去掉页面蓝灰渐变 | `VeriPage`、主题、记账背景 |
| 内容 | 稳定实体表面、20dp 卡片圆角、弱边框、无装饰阴影 | `VeriCard`、资产净值封面 |
| 控件 | 12dp 输入/按钮、16dp 中型控件；分类和账户保持已有语义 | 主题令牌与既有组件 |
| 标题 | 页标题 22dp、分组 16dp、辅助标题 12dp，Header 64dp | `VeriHeader` 与共享 textTheme |
| 金额 | 主金额更突出；金额仍使用原类型颜色和格式化口径 | 首页、资产、记账 |
| 首页 | 三项摘要复用原指标方块，预算保留圆环；卡片纵向内边距小于横向，曲线无光晕 | `HomeTrendPanel`、`BudgetPanel` |
| 列表 | 交易行增加纵向呼吸空间和副文案对比 | `TransactionTile` |
| 我的 | 保留原四列宫格和入口位置，仅统一材质、标题和间距 | `_FeatureGridCard`；按内容高度适配窄屏 |
| 浮层 | 复用原玻璃导航、锚点菜单、Picker 和根级反馈；不仿造折射 | 既有入口 |

其他页面水平内容边距候选为 20dp、卡片内部默认 18dp；首页为 16dp 页边距和横 14dp /
纵 10dp 卡片内边距。不改变金额、退款、
汇率、预算、保存、返回、平台权限或持久化逻辑。图片型资产封面继续使用原有可读性遮罩。

## 预览与对照

```bash
# 正式应用 + 候选样式，固定端口以复用浏览器预览数据
flutter run -d web-server --web-hostname 127.0.0.1 --web-port 7357 --dart-define=UNIFIED_DESIGN_PREVIEW=true
# 或生成可由静态服务器打开的候选构建
flutter build web --no-web-resources-cdn --dart-define=UNIFIED_DESIGN_PREVIEW=true
```

在真实设置页切换浅/深主题。浏览器保持 393 × 852；另外用 360dp 测试窄屏。
移除参数并重新运行/构建即可恢复默认样式，不会更改账目数据。预览中正常的编辑和
保存依然会写入当前浏览器本地数据，它不是静态截图模式。

正常 Android/Web 构建不带开关，因此继续使用已发布外观。确认后才进行正式迁移，
并删除临时分支判断；不能把这个预览开关永久发展成两套独立设计系统。

本轮扩展测试同时发现默认外观在 360dp 下的个人页宫格高度不足。这个独立的布局
修复对默认构建也生效：按内容/字号预留宫格高度，保持原四列结构，不开启候选设计。
