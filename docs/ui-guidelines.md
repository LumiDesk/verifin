# Veri Fin UI 规范

## UI Lab 预览边界

电脑端的视觉方案先在 `tool/ui_lab` 独立 Flutter Web 工程中验证。该工程不是产品
Web 版，只允许静态演示数据与纯主题/纯展示依赖；不得为了浏览器预览给正式 Controller、
SQLite、KV、备份、AI 或平台桥补 Web 兼容分支。方案确认后迁入正式 `lib/`，最终交互、
性能、权限与生命周期仍以 Android 模拟器/真机验收为准。

## 浮动根导航与中性玻璃

四个根页面统一使用 `VeriRootNavigation`。导航是浮动胶囊，快捷记账是同材质圆形按钮且只在首页显示；非首页隐藏按钮后胶囊居中。选中图标/文字在深色模式使用白色、浅色模式使用黑色，未选中为灰色；Hover 只增强图标/文字，不绘制背景。

承载根导航的 Shell 必须启用 `Scaffold.extendBody` 并关闭 body 外层 `SafeArea` 的 bottom 裁切，页面内容需延伸到玻璃背后，不得留下整宽底栏底色。PageView 外必须套 `VeriRootNavigationBody`，隔离 Scaffold 注入的 bottom padding，避免页面内未显式 padding 的 GridView（日历、功能宫格等）被底栏高度撑大。导航在系统安全区之外再保留左右、底部各 24dp 外边距；四个根页面列表使用 `veriRootPageListPadding(context)` 按保存的实际底栏高度避让末项。

玻璃层禁止手写线性/径向渐变、固定品牌染色或额外顶部高光线；只允许均匀中性透明色、背景模糊、单一轮廓和阴影。品牌蓝只用于圆形快捷记账的加号等明确主操作，不用于选中 Tab。真正的背景折射/色差必须使用单独评估并验证过的 Android Shader，不能用静态渐变冒充。

滑块按下缩放到 94%，按住非当前 Tab 时以 280ms 柔顺追向手指，移动超过 2px 后连续跟随，松手以 240ms 吸附最近目的地，缩放回弹 160ms。不得退回到 `GestureDetector` 默认水平拖动阈值，否则会重现“起步卡一下”和远距离按下直接跳转。完整状态机、研究记录和测试范围见 `docs/dev/liquid-glass-navigation.md`。

## 顶部 Header 与页面骨架
所有页面顶部统一使用 `VeriHeader` 或 `PageHeader`。Header 固定高度（`veriHeaderHeight`），支持返回、标题、副标题和右侧操作。不要在页面内手写顶部 `Row + IconButton + Text`，避免不同页面高度和对齐不一致。

**新建页面一律套用同一套骨架**，否则头部会和其它页对不齐：

```
Scaffold(
  body: SafeArea(               // SafeArea 在外、VeriPage 在内（顺序固定）
    child: VeriPage(            // 渐变背景 + 居中 + maxWidth 约束
      child: ListView(
        padding: const EdgeInsets.fromLTRB(14, 8, 14, 40),  // ← 头部对齐的关键
        children: [
          VeriHeader(title: ..., showBack: true, actions: [...]),
          // 其余内容...
        ],
      ),
    ),
  ),
)
```

**关键点**：`VeriHeader` 自身**没有横向内边距**——所有页面头部的左右缩进（14）与顶部间距（8）全靠这层外层 `padding: fromLTRB(14, 8, 14, …)`。少了它，标题栏会贴边、和别的页对不上（AI 助手页曾犯此错）。

**带固定页脚的页面**（如聊天页底部有输入栏，不能整页放进一个 `ListView`）：用 `Column`，但**必须单独给头部套上同样的内边距**，否则同样错位：

```
SafeArea(child: VeriPage(child: Column(children: [
  Padding(
    padding: const EdgeInsets.fromLTRB(14, 8, 14, 0),
    child: VeriHeader(title: ..., showBack: true),
  ),
  Expanded(child: ListView(padding: EdgeInsets.fromLTRB(16, 14, 16, 18), ...)),
  _FooterBar(),   // 固定页脚在 Column 末尾
])))
```

参照实现：`report_analysis_page.dart`、`ai_settings_page.dart`（ListView 版）；`ai_chat_page.dart`（Column + 固定页脚版）。

### 编辑页保存与返回

普通全屏编辑页在 `VeriHeader` 右侧使用 `SaveHeaderAction`，统一显示软碟语义的 `Icons.save_outlined` 和“保存”tooltip；不要用对勾同时表达保存、完成和确认。草稿未修改或校验未通过时保存按钮禁用，字段编辑期间不得直接写 Controller、SQLite 或 KV。

全屏编辑页使用 `UnsavedChangesGuard` 统一处理 Header 返回、Android 系统返回和预测性返回。草稿无变化时直接退出；有变化时显示“保存 / 不保存 / 取消”：保存成功后退出，不保存丢弃草稿后退出，取消继续编辑。持久化失败必须留在原页并保留草稿。Sheet/Dialog 若属于父编辑页，只能更新父页草稿；独立编辑 Sheet/Dialog 的自身保存按钮可作为最终提交动作。

## 卡片标题
首页和功能卡片标题统一使用 `titleMedium` 加 `FontWeight.w800`，与“日历”卡片标题保持一致。不要为单个卡片手写更大的标题字号；需要右侧入口时使用统一的标题行组件或同等字号的 `Row`。

## 品牌图标
应用图标源文件位于 `assets/brand/verifin_icon.svg`，当前使用 tessera 风格的浅色圆角底和三层半透明色块。Android launcher 图标应从同一源文件生成，避免不同尺寸出现不一致的图标风格。

## 选择器
项目内 2–8 项、静态、受控且无需搜索/分区的短单选默认使用 `VeriAnchoredChoice<T>`，贴近 `SettingsRow`、`FilterPill`、`SelectField` 或 `DetailInfoRow` 展开；动态、较长或需要分区的简单列表继续使用底部弹出的 `showOptionSheet`，账户、分类、货币、标签等领域选择使用各自的 `show*PickerSheet`。除非选项需要持续可见且高频切换，否则不要新增页面内分段按钮；连续输入与系统日期时间继续使用专用控件。

底部选择器标题保持简短，选项使用 44px 以上触控高度，当前选项显示蓝色弱背景和对勾。资产页右上角操作、账本/分类/标签/汇率历史行操作，以及设置、备份、AI、周期规则、交易筛选、收支统计、账户/交易编辑、个人资料、附件来源和资产显示设置里的短选择使用锚点菜单；资产背景的在线预设通过同一卡片的递进子菜单选择。动态长列表、标签分区筛选、账单日/周期起始日、导入映射和安全确认不得为了形式统一而迁移。

交易列表的搜索和二级筛选应放在同一个紧凑筛选卡片内。关键词搜索使用可清空输入框，账户和分类继续使用底部选择器；筛选后无结果时展示居中的空状态和明确的“换筛选条件”提示。

交易列表多选：从右上角「多选」按钮或长按任意交易进入多选模式，进入后行首显示勾选圈、命中行浅蓝高亮，标题显示已选数量，右上角切换为退出多选。底部固定操作栏提供全选、改分类、改账户、删除四个动作（删除用红色），未选中任何项时批量动作置灰。批量删除需二次确认；批量改分类只作用于与目标分类同类型的交易并提示实际改动数量。

账户图标选择器使用底部列表，不使用网格 Tag。每行左侧展示实际图标，右侧展示名称和分组；SVG 账户图标统一放在 `assets/account_icons/`，渲染入口使用 `AccountIconBox`，不要在账户列表中直接手写 `Icon(iconForCode(...))`。

记账详情页“全部分类”弹层使用列表行展示分类，不使用多列 Tag，确保分类名称较长时仍可读。多级分类按层级缩进渲染，父分类行尾用展开/收起箭头切换子分类，点选任意层级（父或子）即选中该分类。

系统日期和时间选择器必须跟随当前应用语言（zh/en）本地化，避免月份、按钮或时间制式与应用语言混杂。

## 弹窗与确认
底部弹窗用于普通选择；`AlertDialog` 只用于破坏性操作、不可恢复操作或必须确认的风险提示，例如删除交易、删除账户、导入数据和初始化数据。

### 锚点菜单

与当前页面上下文强相关、选项数量较少的显示方式、排序、筛选和更多操作，可使用 `VeriAnchoredMenuAnchor` / `VeriAnchoredMenuButton` 贴近触发器展示；静态受控单选优先使用其轻量适配层 `VeriAnchoredChoice<T>`。菜单项支持图标、标题、副标题、分割线和选中/禁用状态；存在下一级时，右侧用箭头提示，点击后以更高层圆角卡片覆盖原卡片并保留可见层级边缘，系统返回优先退回上一级。点击菜单外部关闭整个菜单。

菜单只承载轻量操作和少量枚举选项；账户、分类、长列表、搜索、连续输入、危险确认及需要完整草稿保存的设置仍使用各自 Sheet、Dialog 或全屏编辑页。菜单文案与状态由调用方提供，组件不得依赖具体业务 Controller。

菜单保持紧凑：根菜单默认宽度 224、子菜单默认宽度 232，调用方可分别通过 `width` / `submenuWidth` 配置，单个父项还能用 `VeriMenuItem.submenuWidth` 覆盖自己的子菜单宽度；允许收窄到 168。主标题使用项目 `titleSmall`（13px），副标题使用 `labelMedium`（11px），单行操作的实际触控高度不低于 44px。Web/桌面 Hover 必须是与面板四边留出一致间距的圆角矩形，不能把整行铺成横条。

图标占位按菜单项自身决定：有图标的项才预留图标列，纯文本项直接从统一内容左边距开始，不得因为同组标题或其他项带图标就人为缩进。

递进动画以被点击菜单行的实际位置为原点：该行保持图标、标题、副标题与箭头的连续性，容器从行高平滑展开为子菜单卡片；返回时按相反过程收回原行。原菜单在展开期间使用黑色混合压暗，但表面保持完全不透明，禁止通过整体 `Opacity` 弱化或改成更亮的卡片。

多级菜单必须保留完整祖先卡片栈，不能只渲染“上一层 + 当前层”而让更早层级消失。每深入一级，已有层按距当前层的深度继续轻微缩小（每层约 3%，最低 88%）并加强压暗；最近父层最大、最清楚，远层更小、更暗，形成稳定的纵深关系。所有祖先层仍保持各自累计展开原点，返回时逐层恢复尺寸和颜色。

选择账户一律使用账户选择弹窗（`showAccountPickerSheet`），行样式与资产页账户列表一致：左侧账户图标，中间账户名称（含灰色卡号后四位），右侧余额（负数红色、非负青绿色、不计入资产弱化色）。记账页的账户选择框前置图标必须跟随所选账户的图标，不使用固定图标。

## 设置与信息行
设置类行统一使用 `SettingsRow`。左侧放图标和标题，右侧数据必须靠右显示；可点击行使用右侧箭头。设置行保持紧凑但触控高度不低于 44px，不要在设置卡片中手写不对齐的 `Row`。

数据导出使用设置行直接生成备份，并用轻量提示反馈结果，提示文案必须说明 Android 端文件位于系统下载目录。未加密备份是 `.zip`（`backup.json` + 独立附件），加密备份是 `.json` 信封；Android 端优先通过系统 Downloads 写入，不依赖文件保存弹窗。数据导入必须先展示确认弹窗，说明会替换当前本地数据；确认后再打开文件选择器，失败时使用清晰错误提示。检查更新使用设置行触发，不自动检查；点击后打开弹窗展示当前版本、最新版本和状态。有新版本时由用户点击“下载新版本”，下载期间必须展示进度条或百分比，并禁止通过遮罩或系统返回关闭弹窗、重复发起下载；下载完成并通过完整性与包信息校验后再打开系统安装确认。已下载的同版本安装包在弹窗重开后仍应提供“立即安装”，不得要求重复下载。

账户详情中的类型、名称、图标、单行备注、分组等字段应直接做成可点击设置行；信用卡和储蓄卡需要显示并可编辑卡号后四位。计入资产和隐藏账户使用紧凑开关行，不使用完整高度的 `SwitchListTile`。

隐藏账户不混入普通资产分组；资产页分组列表末尾显示“n个隐藏账户”入口，进入独立页面查看隐藏账户列表。

资产页账户列表支持分类视图和类型视图。普通资产页只负责浏览：每个分区标题行可点击临时展开/折叠，右侧展示分区总额和展开箭头；折叠状态不持久化，也不在浏览页直接拖拽。视图模式、资产卡片背景、分区顺序和分区内账户顺序集中在独立「资产显示设置」页，所有修改先进入页面草稿，右上角软碟保存后一次提交；分区通过手柄拖动，账户通过长按拖动，开启触感反馈时同步提供轻触感。排序按账本和视图模式持久化；新增账户默认进入所属分区末尾的未排序区域，不主动重排已有顺序。信用卡和储蓄卡如填写卡号后四位，账户名称后展示灰色 `(1234)` 标记。

分类管理页使用统一 Header、分段类型切换和紧凑列表行，并按多级树形结构缩进展示：父分类行左侧用展开/收起箭头切换子分类，子分类按深度缩进。Header 的加号新增顶级分类；普通模式点击行或行尾更多按钮打开锚点菜单，“编辑”子菜单提供重命名、换图标、新增子分类、移动到（选择新父级或“顶级分类”）和合并。排序使用右侧拖动手柄且仅在同级之间生效，不构造菜单。删除分类属于破坏性操作，必须先确认；已有交易引用的分类、以及仍有子分类的父分类只能提示原因，不能直接删除。系统分类（余额调整）不显示移动、合并或删除。

## 卡片交互
卡片默认只用于承载信息。需要点击跳转时应提供明确入口或使用轻量点击反馈；首页趋势卡、预算卡这类大面积入口不使用长按高亮卡片态。

长按只用于低频配置入口，并且必须提供可见提示。资产净值卡片背景点击右上角图片图标进入「资产显示设置」，选择/裁剪结果仍是草稿，必须点击该页右上角保存后生效。图片型卡片使用 `BoxFit.cover` 做封面裁剪，文字层必须增加遮罩或渐变以保证可读性。本地上传的大图应先裁剪压缩后再写入本地存储。

资产净值卡片默认无背景图时使用普通卡片背景和普通文本色；只有用户设置背景图后才使用轻量黑色可读性遮罩和浅色文字，不叠加蓝色、紫色等品牌色渐变。卡片内容顺序为：净资产标题和背景图标、净资产金额、资产/负债摘要、底部资产趋势图。资产趋势图高度需要明显高于普通小图，避免显得压扁。

## 图片裁剪
头像、资产背景和后续类似图片入口统一使用独立裁剪页。头像使用 1:1 圆形预览，资产背景使用与实际净资产卡片一致的宽幅封面比例预览。裁剪页至少提供缩放、水平位置、垂直位置和重置操作，确认后再写入本地数据。本地图片以 data URL 保存时，预览和正式展示必须使用内存图片渲染，不要用网络图片组件直接加载 data URL。

## 金额显示
金额为 0 时统一显示 `0`，使用中性色，不显示 `-0` 或红色。支出、收入和转账颜色只在金额非 0 时表达语义。

记账详情页顶部大金额颜色跟随当前类型：支出用 `veriExpense` 红色，收入用 `veriIncome` 青绿色，转账用 `veriBlue` 蓝色。

金额精度按 ISO 4217 minor unit：JPY/VND 等 0 位、CNY/USD/EUR 等 2 位、KWD/BHD/OMR 等 3 位；「精简尾零/标准精度」只控制显示，不改变持久化值。新代码使用 `formatMoney` / `formatSignedMoney` / `formatCurrencyNumber`，不得用固定两位的旧 helper 格式化多币种金额。

单币上下文可用货币符号；交易列表、混币账户列表、导入预览和任何存在符号歧义的上下文必须显示 ISO 三字母代码。普通交易以原币为主金额，原币、账户币或本位币不同时在次级行说明账户实际金额和冻结本位币金额；跨币转账同时展示两端账户的真实金额。

预算、首页/看板汇总、统计和 AI 结果统一标明账本本位币。资产账户行显示原币余额，总资产显示本位币估值；缺任一必要汇率时使用明确缺率空态，不能显示部分总额，也不能把缺失点画成 0。

## 预算页面
预算体系拆分为查看执行情况与管理单期覆盖的 `BudgetOverviewPage`，以及集中维护默认值的 `BudgetSettingsPage`。总览页顶部使用月份切换器，主体展示预算进度圆环、本期支出、剩余额度、剩余日均和预算金额；月预算状态标签用于区分“沿用默认/本期单独”，点按只调整该期覆盖。右上角齿轮进入设置页，集中配置默认月预算、按日上限、预算周期起始日和分类默认预算。近 6 期趋势使用支出柱和预算线，必须带周期标签和纵轴刻度；历史对比保持紧凑摘要。分类预算树在总览页默认折叠，点分类行主体管理所选月/期的单期覆盖，父分类左侧箭头只展开/收起子树；设置页的分类行仍只编辑默认预算。首页预算卡只展示最需要关注的单个分类提醒，正常状态不打扰用户。金额输入继续使用统一数字键盘，不新增复杂图表。

## 快速记账弹层
快速记账数字键盘必须是内容高度的底部弹层，不占满全屏。弹层内部保持移动端最大宽度、底部安全区和 4:3 数字按键比例。

数字键、退格、`C`、小数点和正负切换使用统一弱背景按钮，不使用蓝色边框；浅色模式为浅底深字，深色模式为深底浅字。`OK` 可点击时使用主蓝色背景和白色文字，不可点击时使用清晰的浅蓝灰禁用态。

数字键盘按键默认触发系统触感反馈；设置页必须提供“触感反馈”开关，关闭后数字键、退格、清空、金额确认都不触发触感。

## 图表交互
所有数据图表都必须支持交互，后续新增图表同样遵守。曲线图和柱状图统一使用 `InteractiveTrendChart` / `InteractiveBarChart`（`lib/app/chart_painters.dart`）：点击或横向滑动选中数据点/柱子，绘制竖向参考线和高亮点，并通过 `drawChartTooltip` 弹出统一样式的数据气泡（深色底、浅色文字，自动夹紧在画布内，浅色/深色/图片背景下都可读）；再次点击同一位置或点击图表区外取消选中。多序列图表（如预算趋势的预算线+支出柱）气泡内用同色小圆点区分序列。看板环形图点击分段后中心展示该分类的名称、金额和占比，其余分段弱化。

图表区域必须拦截点击：位于可跳转卡片内的图表（如首页支出走势卡）点击只展示数据，不触发卡片跳转；跳转仍由卡片其余区域承担。

## 图表周期
首页概览卡与看板日趋势使用**累积展开窗口**（`cumulativeWeekWindowFor`）：起点恒为当月 1 号，终点按 7 天为步长推进——1–7 号显示 1–7、8 号起显示 1–14…… 直到覆盖整月为止，不直接把未来日期塞进横轴。收支统计详情页按整月窗口（`monthWindowFor`）展示，配合月份切换查看任意月份。天数较多时 x 轴日期标签用 `sparseLabelsForWindow` **稀疏化**（1 号与每 5 天各标一个，其余留空），避免整月日期挤成一团；滑动时数据气泡仍显示具体某天。

看板圆环图必须横向居中，中心只保留金额等核心数字；分类名称通过与圆环同色的细线从圆环外侧引出，不在右侧放“最高分类”等说明块。分类统计至少展示支出金额最高的 5 个分类，剩余分类统一合并为“其他”。圆环尺寸保持克制，接近首页预算圆环的视觉量级。月度柱状图必须提供纵轴标签；超过 `10000` 的刻度使用 `1w`、`1.5w` 等短格式。

看板预算执行卡放在看板顶部，展示本月预算、支出、剩余/超出、分类预算数量和超支数量。该卡只做执行摘要，不承载预算编辑；编辑仍从首页预算卡进入预算页。
