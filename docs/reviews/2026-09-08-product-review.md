## 3. P0 —— 阻断核心任务或一次误操作即改账

### P0-1 · 首启引导可以不建账户，第一次记账就保存不了，而且页面里没有出口

**证据**：`lib/pages/onboarding_page.dart:84-102`

```dart
// 建首个账户（填了名称才建）。
final name = _accountName.text.trim();
if (name.isNotEmpty) { controller.addAccount(...); }
```

输入框标签是「账户名称（可选）」（`lib/l10n/app_zh.arb:1401`），引导页还有「跳过」按钮（`onboarding_page.dart:137`）。新库的默认账户列表是空的（`lib/app/demo_data.dart:5`）。此时进记账页：

- `lib/pages/entry_detail_page.dart:790-799` 因为 `accounts` 为空，渲染的是 `EmptyState`（「没有可用账户 / 请先在资产页添加或取消隐藏一个账户。」），**而不是账户选择器**——所以能选「无账户」的 `_pickAccount` 入口也不存在。
- `lib/pages/entry_detail_page.dart:1478` 的 `_canSave` 返回 false：`(_noAccount || accounts.isNotEmpty) && ...`，`_noAccount` 默认 false，且只在「编辑既有无账户交易」或「AI 草稿没识别到账户」时才会被置 true（`:146-148`、`:174-181`）。

**影响**：产品第一条主路径走不通。用户看到的是一个保存按钮永远灰掉、空状态里没有任何按钮、只能自己猜到要去「资产」页建账户的页面。

**建议**：引导页把账户名改为必填（或 `_finish` 里种一个「现金」账户）；记账页空状态加「去创建账户」动作；零账户时默认允许「无账户」记账并说明后果。

### P0-2 · 还款页永远「有未保存修改」，点返回时弹窗的主按钮是「保存」，一点就真扣款

**证据**：`lib/pages/credit_repayment_page.dart`

```dart
bool _saved = false;                       // :38
...
isDirty: !_saved,                          // :97 → 进入页面即 true
```

`_saved` 只在保存成功后置位，页面上没有任何其他地方会改写它。而进页面就会：预填全部欠款（`:52-58`）、预填备注「还款」、自动挑好扣款账户（`:71-86`），保存按钮因此默认可用（`:106-108`）。未保存对话框的主按钮是「保存」（`lib/app/common_widgets_forms.dart:430-434`）。

**影响**：用户只是打开看看欠多少 → 点返回 → 弹「此页面有尚未保存的修改」→ 顺手点高亮的「保存」→ 立刻写入一笔真实转账并改变信用卡余额。这是**静默改账**，比「记不上」严重。

**建议**：照 `lib/pages/account_detail_page.dart:893-895` 的做法，用「金额/扣款账户/日期/备注 vs 初值」的显式指纹判断脏状态；未改动直接退出，不弹窗。

### P0-3 · 忘记应用锁即永久锁死，而帮助文案指向锁屏之外的入口

**证据**：`lib/pages/app_lock_page.dart` 全文没有「忘记」入口（grep 无命中），锁屏只提供 PIN / 图案输入与生物识别。帮助文案（`lib/l10n/app_zh.arb:2302`）写「…无法找回；忘记时可在设置页初始化数据后重新设置。」——但 `lib/pages/app_lock_gate.dart:64` 的 `showLock = _locked && controller.appLockEnabled` 成立时，整个应用被 `Offstage` 覆盖，**设置页根本进不去**。同时没有失败次数限制或冷却。

**影响**：用户一旦忘记，全部本地账目永久不可达，而应用给出的唯一指引做不到。

**建议**：锁屏加「忘记密码？」→ 进入二次确认的「初始化数据」流程（文案明确写清会删除全部本地账目）；同时加 N 次失败后的冷却。

## 4. P1 —— 真实摩擦（15 项）

### 术语与信息架构

- **P1-1 · 报销/退款一个概念 8 个名字**：`待报销`（`entry_detail_page.dart:862`）、`标记待报销`、`退款`、`添加退款`、`退款 / 报销回款`（`refundLabel`）、`待退款`（页面标题）、`已退`（行徽标）、`已报销`（筛选值）、`已冲抵`。且筛选语义互相矛盾：`lib/pages/transactions_pages.dart:105-114` 中 `pending` 匹配「已标记且净额非零」、`reimbursed` 匹配「`refundedBaseAmount != 0`」，部分回款会同时出现在两个筛选里，行徽标却显示「已退」。**建议**：状态统一叫「待报销」，关联条目统一叫「回款」；在开关下加一行说明「标记本身不产生资金变动，到账才冲抵净额」。
- **P1-2 · 资产口径四个名字**：`净资产` / `资产 {amount}`（`assets_pages.dart:288`）/ `总资产` / `资产总额`（桌面小组件）指代同样两个数字。**建议**：固定「总资产 = 正余额之和」「净资产 = 净额」「负债 = 欠款」。
- **P1-3 · 分析页命名混乱**：底部 Tab 叫「看板」、页头副标题叫「数据看板」、另一页叫「统计分析」、我的宫格副标题叫「报表」、首页趋势卡进入的叫「收支统计」、默认卡片标题叫「概览」；同一排行在 `分类明细` 与 `分类排行` 之间摇摆。**建议**：看板 = 仪表盘，统计分析 = 深度分析，排行列表两处统一叫「排行」。
- **P1-4 · 看板没有收入，且「月度收支」实际只画支出**：`lib/pages/reports_page.dart:47-70` 全程只取 `EntryType.expense`，`monthlyExpenseValues`（`lib/app/ledger_math.dart:273-282`）也只有支出，而面板名叫「月度收支」。**建议**：看板顶部补一条本月收入/支出/结余摘要；或把该卡改名为「月度支出」。

### 缺失与不可达

- **P1-5 · 看板 6 个面板里 4 个没有空状态**：分类圆环（`reports_page.dart:83-106`）、日趋势（`:130-172`）、月度结构（`:173-223`）、预算趋势（`budget_trend_chart.dart:24-113`）在无数据时只画空网格或灰色轨道，而旁边两张卡却正常显示空态文案。**建议**：四张图统一套 `EmptyState`。
- **P1-6 · 预算页可能彻底不可达，看板预算卡是死链**：`BudgetOverviewPage` 全仓唯一入口是首页预算面板（`home_page.dart:160`，已核实），该面板可被用户在面板管理里关掉；看板的预算执行卡没有任何 `onTap`（`reports_page.dart:335-464`）；未设分类预算时卡片显示绿色的「正常」。**建议**：「我的 → 数据与工具」加「预算」入口；看板预算卡可点；`budgetedCount == 0` 时改文案。
- **P1-9 · 交易列表无法直接记一笔；「待退款」藏在图标里且为空时彻底消失**：`transactions_pages.dart:260` 的 `Scaffold` 没有 `floatingActionButton`（已核实），而全局 FAB 只在首页显示（`shell.dart:173`）；「待退款」入口仅在 `pendingRefunds.isNotEmpty` 时渲染，为零时全应用没有第二个入口。**建议**：交易列表加 FAB（预填当前筛选日期）；「待退款」改常驻。
- **P1-10 · 时间筛选不计入空态与「清空筛选」**：`transactions_pages.dart:601-606` 的 `_hasSecondaryFilters` 不含 `_timeFilter`，于是只设时间筛选时显示「暂无交易 / 保存交易后会在这里按日期展示。」，清空按钮也不重置它。**建议**：纳入判断与 `onClear`，并显示可单独清除的时间筛选 chip。
- **P1-11 · 跨币种还款是死路，缺汇率提示只告知不可操作**：`credit_repayment_page.dart:95` 的 `canConfirm` 在跨币种且未填转出金额时恒为 false，页面没有维护汇率的入口；资产页缺率提示卡同样不可点（`assets_pages.dart:372-412`）。**建议**：缺率字段直接可点进 `editExchangeRate()`。
- **P1-13 · AI 几乎不可发现，且从没告知聊天记录不进备份**：引导页文案没提 AI，「我的」宫格 9 个入口没有 AI（已核实：`AiChatPage` 唯一入口是 `reports_page.dart:266` 的一个图标按钮）；聊天历史只存 KV、不进导出，页面无说明；超过 40 条会静默丢弃最旧记录（`ai_chat_page.dart:71, 158-160`）。**建议**：「我的」加「AI 财务助理」入口；聊天页头加一行「对话只存本机、不含在备份内」。

### 信任与安全

- **P1-12 · 隐私政策与实际网络行为不符（完全没提 AI）**：`lib/app/legal_content.dart:54` 写「网络：仅用于『检查更新』时访问 GitHub Release，不会上传你的任何数据。」，全文 grep「AI」零命中；而 AI 功能会把用户输入与只读账目摘要发到用户自配的第三方端点（该说明只在**同意之后**的 AI 设置页出现）。**建议**：政策正文增加「AI 与第三方服务」一节并更新 `legalUpdatedAt`。
- **P1-14 · 数据安全：让用户「先备份」却不给路，导入全失败仍报「完成」**：恢复确认框（`data_management_page.dart:1540-1545`）建议先导出，但对话框只有「取消 + 确认」；全部行失败时标题仍是「导入完成（成功 {count} 笔）」；「清除备份目录」无确认（`:767-772`）；本地导入吞掉具体错误原因，只显示「备份文件格式不正确」。**建议**：确认框加「先导出再继续」；`importedCount == 0` 改标题；清目录加确认；错误改用 `error.message` 并做统一映射。

### 交互与可达性

- **P1-7 · 设计令牌对比度普遍不达 AA**：`lib/app/app_theme.dart:41-48` 的 `veriIncome #12B8A6` 在白底上仅 **2.49:1**（已复核计算），却被用作收入金额、正余额、日历收入与「已退」徽标；`veriWarning #FFB33E` 1.78:1、`veriBlue #3498DB` 3.15:1、`veriExpense #E84D6A` 3.68:1。另有一条「弱化文字」阶梯用到 alpha 0.35–0.44（约 2.2–2.8:1）。**建议**：给语义色加浅色变体（如 `veriIncomeLight ≈ #0B7A6C`），弱化文字浅色底不低于 alpha 0.62；`entry_sheets.dart:264/269` 已有明暗分支先例。
- **P1-8 · 大量触控目标低于 44dp**：`app_theme.dart:119-125` 的 `TextButton` 是 `minimumSize: Size(36,34)` + `tapTargetSize: shrinkWrap` + 全局 `visualDensity: compact`（已复核），有效点击区约 28×26，影响**每个对话框的「取消/不保存/删除」**；`IconButton` 约 40×40；`CompactSwitchRow` 整行不可点且开关被缩到约 39×39；`FilterPill` 36dp；记账页「更多信息」胶囊约 30dp；分类子级省略号浮标仅 18×18。**建议**：`TextButton` 提到 `Size(48,44)` + `padded`；开关整行可点；浮标提到 ≥32dp 并保留「再点父分类」的备选路径。
- **P1-15 · 记账页：自动识别静默改写字段；多币种主金额无单位；保存禁用无原因**：自动识别默认开启（`veri_fin_controller_state.dart:130`），进页面即改写类型/分类/标签/备注（`entry_detail_page.dart:465-508`）且界面无任何标记；主金额用 `formatCurrencyNumber`（`currency_math.dart:29-44`，不附加币种），多币种下「100」无从判断币种，数字键盘同样不显示币种；退款超额时保存按钮置灰但无提示（`transaction_detail_page.dart:140-151`）。**建议**：自动填充的字段加弱化「自动识别」标记；主金额改用带单位的 helper；禁用时在页面内给出红色原因行。

## 6. 已核查、未发现问题的区域

- **国际化**：中英 ARB 各 1265 条，键集完全一一对应（已用脚本核对）；页面层无硬编码中文。
- **缺汇率不产生「部分和」**：资产页主数值、分区合计在缺率时显示 `—`，走势图显式缺率空态，桌面小组件用 `completeTotal`；零余额不要求汇率。
- **破坏性操作守卫**：删除交易/批量删除/删除退款/删除账户/删除分组/删除汇率/删账本/初始化/清除密钥/清除 WebDAV 均有确认并说明后果；唯一例外是「清除备份目录」（见 P1-14）。
- **数据库打开失败页**：文案诚实且给出正确指引，只缺一个「重试」按钮。
- **持久化失败有用户反馈**：`onPersistError` → 根级轻提示，编辑页保存失败会留在原页并保留草稿。
- **金额为 0 的中性色与 `-0`**：`normalizeCurrencyAmount` 把 `-0` 归零，`formatSignedMoney` 等对零短路；残留的 `+0`/`-0.00` 仅来自手拼字符串（见 P2-2）。
- **多币种三层金额、信用卡计算、资产排序持久化**：口径与测试均正确。
- **空状态覆盖**：交易列表/搜索无结果/待退款/退款/隐藏账户/汇率/汇率历史/周期规则/分类预算/预算历史都有空态文案。
- **AI 草稿必须确认**：AI 记账/截图/分享/Intent 只产草稿；AI 工具只读。
- **引导币种时机**：本位币在「首个账户之前」就已选定并应用到空账本。
- **轻提示队列**：去重/优先级/丢弃与生命周期暂停逻辑正确。
- **数字键盘按键尺寸**：360dp 下约 78×58dp，配色随明暗模式。

## 7. 同类产品做法对照

对照范围：中国市场（钱迹、随手记、鲨鱼记账、一木记账、薄荷记账、蜜蜂记账 BeeCount、挖财、一羽记账）与西方市场（YNAB、Copilot Money、Monarch、Spendee、Actual Budget、Firefly III、Cashew、Ivy Wallet）。来源为各产品官方文档/帮助中心、应用商店页面、GitHub README 与用户社区，链接见文末。

### 7.1 记账入口：本产品的方向是对的

市场分成两派：**有银行同步的西方付费应用以「核对」为主**（Copilot 的手动记账是 7 个字段的表单，帮助中心里根本没有「快速记账」这个词）；**没有银行同步的中文应用以「键盘优先 + 智能预选」为主**。因为 Veri Fin 不做银行同步，正确的对标对象是后者，而本产品已经在做：

- 金额键盘 + 分类胶囊 + 默认付款账户 + 桌面小组件 + 快捷磁贴 + 分享入口，与钱迹、一木的做法同向。
- **算式键盘是真正的差异化**——中文市场只有钱迹等少数产品内置计算器式输入。
- 可补的两点：钱迹的默认账户是**按分类记忆「上次用过的账户」**（本产品目前是每账本一个默认账户，见 §8 新增条目）；一木的「通知栏常驻统计 + 点击即记」也值得参考。

### 7.2 信息架构：独立的「看板」Tab 不符合中文市场惯例

中文市场几乎统一的四 Tab 是 **明细（首页）/ 资产 / 统计 / 我的**；统计是独立评估维度，但没有「看板」这一项——仪表盘内容要么并入首页，要么并入统计。西方银行同步类应用里「Dashboard」本身就是首页。本产品的「看板」既不完全是首页摘要、也不完全是统计，这正是 §4 P1-3/P1-4 混乱的根源：**要么把它定位为「统计」，要么把它并回首页。**

### 7.3 预算：本产品的「剩余日均 + 自定义周期」恰好踩在用户最在意的点上

Monzo 撤掉 Summary（「还剩多少可花」）改用分析性的 Trends 后用户强烈反弹，有人直接弃用；其中一条明确抱怨是 Trends「死板地按自然月」——这**正面验证了本产品自定义预算周期起始日与「剩余日均」的价值**。Copilot 的「可按分类单独开关结转」也是值得抄的粒度。结论：**继续保持「还能花多少」的醒目度，不要为了分析感牺牲它。**

### 7.4 多币种：整个品类的短板，本产品是少数做对的

Actual Budget 明确不支持多币种（只能用硬编码汇率的实验性规则绕过）；YNAB 是「一个预算一种币种」，建议开多个预算；Monarch 与 Copilot 都不换算，Monarch 自己的文档甚至警告混币账户会让「总额产生误导」。做得好的是钱迹（100+ 币种自动换算）与 Cashew（实时汇率）。

**本产品的「缺率不显示部分和、离线汇率、三层金额冻结」比上述绝大多数实现更严谨**，但这也意味着没有现成对标——需要把「缺率时到底发生什么」写成用户能读懂的说明（对应 §4 P1-11：提示要可操作，而不只是告知）。

### 7.5 退款/报销：本产品的模型领先，缺的是「进度可见」

四种流派：YNAB 的「分类法」（用户抱怨最多，含预支、跨月、部分退款）；Copilot 的「Refund 作为一等交易类型」；钱迹的「关联原支出 + 多笔部分退款 + 待报销工作流」；一羽记账的「负数金额」——**一羽已明确表示该方案不再推荐、将改为关联模型**。

本产品的「退款挂在原支出、只有已到账影响净额」与钱迹同档，领先 YNAB 与一羽。可直接抄的具体做法：**xx/yy 的报销进度显示**、一笔支出多笔部分退款、以及**「把报销记录排除出分类统计」开关**。同时要防住这个品类最常见的用户错误——**把退款记成收入，导致统计虚增**。

### 7.6 数据安全：本产品的能力到位，但「话没说到点上」

本地优先阵营（Actual、BeeCount）用来建立信任的话术是：**开源可审计、无广告无追踪、不需要账号、可无限制导出、WebDAV/自建同步、端到端加密备份、以及「备份一个文件就等于备份了整个账本」**。中文市场还有具体的历史创伤：网易有钱 2021 年停服、随手记的 P2P 风波，社区结论是「不受限的导出数据非常重要」。

本产品的加密备份 + WebDAV 恰好命中这批用户最在意的能力，但**隐私政策漏了 AI 这一条唯一的出网点（P1-12）**，而 AI 恰恰是最需要交代清楚的部分——这是能力与表达之间的落差，也是最容易修的一处。

### 7.7 报表：最大的抱怨是「图表太多」，本产品要警惕

用户真正会用的只有：净现金流、分类排行（可点进交易）、预算 vs 实际、同比/环比、日历、年度回顾。Simplifi 用户最集中的抱怨是「图表多到读不动」以及**自动归并的「Everything Else」把真实分类藏起来**。

需要注意：本产品的看板圆环正是「取前 5 + 其余合并为『其他』」（`reports_page.dart:720/735`），与 Simplifi 被诟病的是同一个模式。它在圆环里是合理的取舍，但**「其他」必须可点进去看到明细**，否则会重演同一种不满。

### 7.8 无障碍：这是本产品可以领先的地方

钱迹 2026-08 的无障碍版本是品类里最具体的实践（每个控件有名字、金额播报正负号、保存后有完整语音确认、日期消歧、父分类的焦点模型）。但它**明确没做对比度、字体缩放和色盲配色**。

本产品目前在这三项上也都有欠缺（P1-7 对比度、P2-7 图表无 `Semantics` 且不跟随字号、P2-8 大字号溢出）。也就是说：**这是一块竞品主动留白的领域，而本产品当前是不及格状态**——补齐的性价比很高。

## 9. 建议的处理顺序

1. **立刻**：P0-1（引导建账户）、P0-2（还款页脏状态）、P0-3（应用锁找回）——三处都是「一次误操作 = 数据损坏或不可用」。

4. **持续**：P2 的格式化统一（P2-1/P2-2/P2-3）与硬编码色清理（P2-4）适合随手改。
